# 劳动法 AI 顾问系统 · 产品设计

> 版本：v1.0（2026-11-07）  
> 主线：劳动者咨询 + 劳动合同合规审查。本文件只定义"产品为什么这样做与用户怎么用"；架构与接口细节见《项目大纲与技术选型》和 `contract/openapi.yaml`。

## 1. 产品定位

劳动法 AI 顾问是一个面向普通劳动者与中小企业 HR 的垂直法律工具。它不做"像律师一样自由聊天"的泛法律助手，只把两个高频、可标准化、有明确证据的问题做扎实：

1. **咨询**：用户描述具体情况，系统给出结论、理由、可查证的法条引用与下一步建议。
2. **审查**：用户上传劳动合同 PDF，系统抽取关键要素，按规则识别违法或不利条款，给出风险等级、原文定位和修改建议。

产品的核心竞争力不是回答得"更像律师"，而是回答得"可核查、可定位、可执行"。所有法条正文必须来自知识库，禁止模型现场生成；所有审查发现必须能点击回到合同原文位置。

## 2. 用户与场景

| 用户 | 核心任务 | 产品回答 | 边界 |
|---|---|---|---|
| 劳动者 | 判断试用期、解除、工资、加班、社保等事项是否合法，以及下一步怎么做 | 结论 + 法条依据 + 行动建议 | 不预测具体诉讼结果，不代替律师 |
| 企业 HR / 小企业主 | 上传合同，找出违法或显失公平的条款 | 风险清单 + 原文高亮 + 修改建议 | 不输出完整改写后的合同 |
| 法学同学 / 评审 | 检查法条、规则与演示流程是否可信 | 引用、命中率、规则覆盖率 | 不作为公共判例研究平台 |

演示主线按劳动者优先展开：一个具体问题可以在 3 分钟内从提问走到带引用的回答；一份真实合同可以在 10 分钟流程里走到逐条高亮与建议。

审查页是最终演示的一等界面：风险总览不能只是"通过",必须展示多少条命中、整体风险等级与已扫描页数，让用户判断这份结论是扎实还是空泛。

## 5. 关键流程

### 5.1 咨询

1. 用户登录后进入问答页，输入具体问题。
2. 系统显示 meta 占位气泡，随后展示"正在检索法条"。
3. Agent 先调 `retrieval.Retriever`：口语归一（"加班费"→"加班/延长工作时间"）后多路召回，命中条文作为依据。
4. Agent 拼 prompt，并通过 `Client.ChatStream` 流式生成。
5. 每个 delta 实时落到回答气泡；命中法条以 citation 事件推送。
6. 回答结束后，引用卡片可展开看原文与跳转链接。**实现状态**：`依据 / 建议 / 可选追问文案` 三个独立区块未做，结论与建议由模型写在正文里，引用以卡片呈现。

失败策略：检索失败时先向用户说明"暂时无法检索法条"，让模型给出通用建议但不伪装引用；模型上游失败允许重试，回复未生成 delta 前才可重试；生成已经开始后不得重试，避免前端重复文本。

### 5.2 合同审查

1. 用户上传 PDF，系统校验大小、页数和文件头。
2. 文件相同则复用旧解析结果；否则解析出页号、文本块与坐标。
3. Agent 抽取期限、工资、试用期、工时、社保、竞业、违约等关键字段。
4. 规则引擎按领域规则逐条判定。
5. 每条 finding 绑定证据、风险等级、法条依据和修改建议。
6. 一律异步：返回 task_id，前端每 2 秒轮询一次进度。一次审查实测 17–110 秒，同步返回会被网关掐断。**实现状态**：恒 202（`contract/openapi.yaml` 已标注同步 200 分支不做）。
7. 前端打开审查页，从侧栏点击某条 finding，PDF highlight 到对应 block。**实现状态**：锚点是 `clause_ref{section, page, bbox}`，不是 block_id。

失败策略：扫描件不给模糊结果，直接提示文本层不可用；某条规则失败只降级该条；解析置信度过低时建议换清晰 PDF 或人工确认。

## 6. 产品状态设计

| 状态 | 产品表现 |
|---|---|
| 上传中 | 显示文件名、大小与进度；禁止重复提交 |
| 解析中 | 显示"已识别页数 / 总页数"，上限 50 页 |
| 解析失败 | 明确区分超限、非 PDF、无文本层三种原因 |
| 检索中 | 显示 tool_call 文案和摘要参数；失败后可继续 |
| 流式回答 | 内容逐字追加，允许中途取消 |
| 引用 | 卡片显示法条号、条文目录、正文片段；原文必须来自库 |
| 审查进度 | 显示 stages：解析 → 抽取 → 风险判定 → 汇总 |
| 单条规则失败 | 该条不是消失，而是提示"暂未计算，其余结论不受影响"（**实现状态**：规则 panic 被隔离、记 50002 日志，该条不出现在清单里；界面上的"暂未计算"提示待补） |

界面不使用"AI 正在思考"这类模糊文案；无论是检索、抽取还是模型生成，都要让用户知道具体在做什么。

## 7. 可信设计

信任来自结构，不来自语气。

**Zero hallucinated statutes.** 法条主体文字只能来自知识库；模型可以解释，不能现场编造条文。citation 事件里必须带 statute_id 与库内 text；没有对应法条时只明确任务是"给出一般建议"，不得伪装引用。

**Every finding is localizable.** 合同审查不能只给抽象判断，必须带 `block_id` 与 `char_start` / `char_end`，并在高亮 layer 上把判断锚回原文。Agent 不碰 PDF 坐标本身，只返回这些稳定锚点。

**Risk is tiered, not scored to fake precision.** 风险分为高 / 中 / 低三档，不人流使用百分比分数。每条 should 明确：是"违法"还是"合法但不利于劳动者"还是"写法不清"。

**Failure is visible.** 当某条规则或检索失败，界面上标记降级，而不是把主算法伪装成系统核心不可用。
