# 检索评测基线

> 本文所有数字来自命令输出，不是估算。改动检索相关代码后必须重跑并更新本文件。

## 语料

`SELECT COUNT(*) FROM statutes;` → `365`，`SELECT COUNT(*) FROM embeddings;` → `365`。

| 法律 | 条数 |
|---|---|
| 中华人民共和国劳动法 | 107 |
| 中华人民共和国劳动合同法 | 98 |
| 工伤保险条例 | 67 |
| 中华人民共和国劳动合同法实施条例 | 38 |
| 劳务派遣暂行规定 | 29 |
| 女职工劳动保护特别规定 | 16 |
| 职工带薪年休假条例 | 10 |

合计 365 条，来自 `SELECT law, COUNT(*) FROM statutes GROUP BY law ORDER BY 2 DESC;`。
向量 365 条 × 1024 维（`text-embedding-v3`），来自 `SELECT owner_type, model, COUNT(*) FROM embeddings GROUP BY 1,2;`。

## 复现方式

```bash
DSN="laborlaw:laborlaw_dev@tcp(127.0.0.1:3307)/laborlaw?parseTime=true&charset=utf8mb4&loc=UTC"
export LLM_API_KEY=$(grep -m1 '^LLM_API_KEY=' .env | cut -d= -f2- | tr -d '\r')

go run ./eval -dsn "$DSN" -mode keyword
go run ./eval -dsn "$DSN" -mode semantic
go run ./eval -dsn "$DSN" -mode hybrid
go run ./eval -dsn "$DSN" -mode rerank
```

**四条命令都必须显式带 `-mode`。** 不传时 `eval/main.go:51-58` 会去看 `RETRIEVAL_SEMANTIC` 环境变量：
该变量为真（本机 `.env` 里就是 `on`）时默认跑 `hybrid`，否则跑 `keyword`。
不写 `-mode` 就得出的结果无法说明自己是什么模式，本文件旧版把一次 `hybrid` 结果记成了关键词模式，就是这么来的。

`-semantic` 是 `-mode hybrid` 的旧写法别名（`eval/main.go:46`），新文档一律用 `-mode hybrid`。

## 当前结果

| 模式 | hit@3 | hit@5 | 零召回 | 命令 |
|---|---|---|---|---|
| keyword | 34/40 **85.0%** | 38/40 **95.0%** | 0 | `go run ./eval -dsn "$DSN" -mode keyword` |
| semantic | 35/40 **87.5%** | 37/40 **92.5%** | 0 | `go run ./eval -dsn "$DSN" -mode semantic` |
| hybrid | 37/40 **92.5%** | 39/40 **97.5%** | 0 | `go run ./eval -dsn "$DSN" -mode hybrid` |
| rerank | 39/40 **97.5%** | 39/40 **97.5%** | 0 | `go run ./eval -dsn "$DSN" -mode rerank` |

原始尾行（2026-11-16，365 条语料）：

```text
keyword ：总结：40 条用例，hit@3 34/40 = 85.0%，hit@5 38/40 = 95.0%，零召回 0 条
semantic：总结：40 条用例，hit@3 35/40 = 87.5%，hit@5 37/40 = 92.5%，零召回 0 条
hybrid  ：总结：40 条用例，hit@3 37/40 = 92.5%，hit@5 39/40 = 97.5%，零召回 0 条
rerank  ：总结：40 条用例，hit@3 39/40 = 97.5%，hit@5 39/40 = 97.5%，零召回 0 条
```

四条命令跑的是同一份 `eval/cases.json`（40 条）与同一个库，差别只在召回方式。
`semantic`/`hybrid`/`rerank` 三档需要 `RETRIEVAL_SEMANTIC` / `RETRIEVAL_RERANK` 开启且 `LLM_API_KEY` 可用，
否则该档会退化成关键词召回，届时输出会与 `-mode keyword` 相同——看到这种结果先查环境，不要当成提升。

## 已知天花板

- **E20（严重违反公司制度被开除，还有经济补偿吗）**：应答 `LCL-39`（过失性辞退无需补偿），
  keyword 档能进 @3，hybrid 档召回 `LCL-46`、rerank 档召回 `LL-28`（都是"一般情形应当补偿"那条）。
  这题本身有歧义——"被开除"既可以指过失性辞退（无补偿），也可以指违法解除（有赔偿金），
  两种读法对应不同条文。不是调权重能解的，需要换判例或问答语料才能让题目本身无歧义。
- **相邻条款的例外/特别规定**（E18、E25 这类）：向量算得出"主题相近"，算不出"这一条正好是例外"。
  rerank 已经把 E18、E25 从 ✗ 捞回 @3，但更大规模的同类问题仍会出现在新增用例里，
  见 `eval/README.md` 的维护约定。

## 已做与未做

- 词表覆盖：`internal/retrieval/keywords.go` 的 `aliases` 收录口语说法与其对应的条文用语，
