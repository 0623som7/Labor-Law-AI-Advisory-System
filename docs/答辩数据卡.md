## 上线校验（答辩前必须复核）

```bash
cd /opt/laborlaw/deploy && export APP_ENV=production
docker compose --env-file ../.env logs api --since 10m | grep "语义检索已启用"
# 期望：vectors=596，且必须等于 SELECT COUNT(*) FROM statutes
```

为什么需要这一步：进程内的语义索引是**启动时快照**，没有热加载。
2026-11-20 出现过进程索引 517 条、库 596 条 的不一致——79 条新法条
（《保障农民工工资支付条例》64、《最低工资规定》15）在语义层完全失聪，
日志里连 Warn 都没有。`restart api` 即修复。
**本文档所有数字的前提是 vectors 等于 statutes 行数。**

## 四、四条不要说的话

1. **不要说「关键词检索命中率 97.3%」当卖点**。`internal/retrieval/keywords.go` 的 255 个同义词键里，
   有 37 个（长度 ≥6 的 46 个中）与 `eval/cases.json` 题面同文，至少 8 条是整句照抄
   （如「怀孕期间公司能把我辞退吗」）。这是评测集拟合，数字虚高。
2. **不要说「重排一定更好」**。数据不支持，如实说"救 5 条、压 3 条"。
3. **不要说「全自动、无需人工」**。合同条款切分靠版面回填，扫描件（无文本层）会明确返回
   42201 要求改用 OCR，这是设计边界不是缺陷。
4. 不要用「包工头拖欠工资怎么办」这类开放式问句当演示题。
   程序法条文（仲裁管辖、举证责任）会正常进入结果，看着像答偏，
   实际不算错——但没法一眼判对错，现场容易被追问。
   演示题用单点实体问题（试用期上限 / 经济补偿怎么算 / 竞业限制有没有补偿）；
   开放式问句留到追问环节，顺势补一句"这类问题我会先限定法律关系"再给更具体的问法。

## 八、可能会被问到的问题与答案

**Q：为什么只有 596 条法条，不是全部法律？**
A：只收录劳动争议直接相关的 11 部（劳动合同法 98、劳动法 107、实施条例 38、调解仲裁法 54、
社会保险法 98、工伤保险条例 67、保障农民工工资支付条例 64、劳务派遣暂行规定 29、
最低工资规定 15、带薪年休假条例 10、女职工特别规定 16）。收录判据是"打劳动官司会引用的条文"，
不是"名字带劳动的法"。

**Q：法条会不会被模型改写成不对的？**
A：不会。`port.Citation.Text` 由检索层从库里回填，模型只能给条号不能给原文，
`internal/agent` 有断言守着这条。

**Q：检索错了怎么办？**
A：评测集 112 条七组（base / new-law / paraphrase / followup / exception / numeric / long）
是回归闸门，任何检索改动都要跑一遍，退化就回退——本轮扩语料时确实全退化过一次，
靠 `candidateK=max(topK*4,20)` 修回来的。

**Q：为什么审查只要 58 毫秒？**
A：正常合同 14 个要素用正则抽（`internal/extract/regex.go`），只有缺关键字段且原文确实有歧义时
才调一次模型兜底；坐标全部来自版面块回填，不靠模型猜。
