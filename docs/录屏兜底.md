# 录屏兜底方案

## 目标

现场网络、部署、浏览器或模型不可用时，用预录视频补位演示。视频必须真实反映系统能力，不允许把 demo stub 输出伪装成真实模型结果。

## 两套录屏版本

1. **真实模型版**：只在已配置 `LLM_API_KEY` 的可用环境录制。片头说明“真实模型演示”，并展示环境已启用模型。
2. **demo stub 版**：没有模型密钥时录制。片头与旁白明确说明“当前为 demo stub，重点展示 Agent 编排、检索、引用和规则审查，不是真实模型生成结果”。

## 录制范围

按 `docs/PPT讲稿.md` 的 3 分钟演示脚本录制，覆盖五个场景：

1. 登录后的对话页空状态。
2. 咨询“公司不给我交社保，我能直接走吗”，展示流式回答、法条卡片和引用。
3. 同一会话追问“那我还能要经济补偿吗”，展示上下文。
4. 上传 `web/e2e/fixtures/contracts/A.pdf`，展示合同审查、风险卡和原文定位。
5. 刷新页面，确认审查结果仍在。

## 录制前检查

1. 运行 API 健康检查：
   - `http://127.0.0.1:8080/healthz`
   - `http://127.0.0.1:8080/readyz`
2. 确认演示合同存在：`web/e2e/fixtures/contracts/A.pdf`。
3. 确认录屏软件分辨率 1440×900，字体足够清晰。
4. 先手动走一遍演示，避免首次冷启动进入录屏。
5. 如果使用真实模型，先跑一次提问并确认回答不为空；如果使用 stub，口播必须说明。

## 命名与存放

录屏文件按日期和版本保存：

```text
docs/assets/2026-11-29-demo-real-model.mp4
docs/assets/2026-11-29-demo-stub.mp4
```

如果文件较大，可以放在答辩演示机本地目录，只把路径写入本页说明，不提交大文件到 Git。

## 现场切换策略

| 现场情况 | 处理 |
|---|---|
| 页面打不开 | 切到录屏兜底，说明“这是提前录制的功能演示”。 |
| 真实模型超时或密钥失效 | 明确说明“上游模型不可用”，切到 demo stub 录屏；不要现场调试。 |
| 合同上传失败 | 切到录屏中合同审查片段，说明本地环境受网络或存储影响。 |
| 检索结果异常 | 说明系统有错误兜底，不会输出无引用的自由生成；切录屏。 |
| 网络中断 | 使用本地 API + 本地前端 + 录屏兜底；没有 Redis 时说明 dev 模式降级。 |

## 答辩口播兜底

> 为防止现场网络波动，我准备了两版录屏：一版是真实模型环境，一版是模型密钥不可用时的 demo stub。stub 版只用于展示系统编排、检索、引用和规则审查，我在演示时会明确标注，不把它当成真实模型输出。
